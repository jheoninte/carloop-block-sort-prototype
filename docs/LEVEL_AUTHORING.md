# 튜토리얼과 레벨 제작

## 현재 단계

튜토리얼 5개와 검토한 20레벨을 보존하고 생성·해법 검증한 280레벨을 더해 현재 300레벨입니다. 30일×하루 10레벨은 사용자가 선택한 분량 가정이며 실제 소진 기간을 보장하지 않습니다.
생성기/시드/설치 절차와 검수 한계는 `docs/LAUNCH_CONTENT_AUDIO_COMMERCE.md`를 참고하세요. 아래 Gemini 인계 절차는 초기 20레벨 팩의 기록입니다.
네이티브 안내/힌트 UI와 안내 확인·완료 기록 저장을 연결했습니다. 기존 두 레벨은 규칙 회귀 검사 전용 fixture에 보관합니다.
원본 Gemini 응답의 수정 내역은 `docs/LEVEL_PACK_REVIEW.md`를 참고하세요.
후속 템포 후보에서 13·18레벨을 교체한 검토와 측정 비교는 `docs/PACING_CANDIDATE_REVIEW.md`에 있습니다. 7레벨 후보는 미반영입니다.

## Gemini 전달

`docs/handoffs/gemini-level-pack-input.txt`는 이번 팩 제작 때 사용한 소스 스냅샷입니다. 후속 작업에는 현재 파일을 다시 묶어 전달해야 합니다.
이 파일에는 현재 코어, 레벨 검사기, 예제 레벨과 출력 형식이 들어 있습니다.
요청 범위는 코드 재작성 없이 `{levels, solutions, tutorials}` JSON 데이터 한 묶음입니다.
`tutorials`에는 레벨별 학습 주제, 예상 난이도, 짧은 힌트와 첫 사출 차량을 기록합니다.

## Codex 통합 절차

1. 응답의 JSON을 후보 파일로 저장합니다. 제작 중인 실제 게임 레벨은 먼저 덮어쓰지 않습니다.
2. 20개 ID/해법/튜토리얼 연결과 지원 규칙, 색상별 수량, 중복/단순 복제 등을 검토합니다.
3. `.\tools\godot.ps1 levels -PackPath <candidate.json>`으로 모든 해법을 실제 GameCore에서 재생합니다.
4. 모든 레벨이 60/120Hz·1배속/2배속에서 클리어되고 블록 총량이 보존되는지 확인합니다.
5. 통과 후 공용 `levels.json`과 `level_solutions.json`에 반영하고 웹 데이터를 동기화합니다.
6. 튜토리얼 UI와 완료 기록을 연결하고, 정답을 강제하지 않는 짧은 첫 안내를 플레이테스트합니다.

검사기는 해법을 탐색하는 솔버가 아니라 제공된 사출 순서를 재생하는 검증기입니다.
클리어 가능성은 확인하지만 최단 해법, 재미, 난이도, 리텐션이나 매출 효과까지 증명하지는 않습니다.
체감 난이도와 학습 효과는 사람이 직접 플레이해 조정합니다.

## 검증 범위

- 현재 20개 레벨: 각 네 가지 프레임/배속 조합, 총 80회 Godot 재생 통과.
- 미완성 해법: 네 조합 모두 실패하며 프로세스 종료 코드 1을 반환하는 것을 확인.
- `HeadlessTest.gd`는 고정 기준 레벨을 사용합니다. 출시용 레벨이 바뀌어도 규칙 회귀 검사의 전제가 변하지 않습니다.
- `godot.ps1 test`는 기준 회귀 검사 뒤 실제 콘텐츠의 `LevelPackCheck.gd`도 실행합니다.
- 후보 검증은 게임 세이브, 현재 레벨 JSON, 해법 JSON을 기록하거나 교체하지 않습니다.
- 튜토리얼 레벨 연결/초점 차량/힌트 길이를 검사합니다. 튜토리얼 확인 및 완료 기록의 저장·복원과 현재 레벨 다시하기도 회귀 검사합니다.
