# iOS 우선 출시 계획

기준일: 2026-11-17. 이 문서는 출시 목표와 작업 순서이며, 미구현 기능의 완료 보고가 아닙니다.

현재 업데이트: 그래픽 보강은 후속으로 미루고, 300레벨 캠페인·원본 음원 12개/음악·수집/완성 연출·상점/모의 구매/복원/광고 보상 흐름을 구현했습니다. Godot 세이브 v5와 알려진 v4 변환도 Windows 검증을 마쳤습니다(`docs/SAVE_MIGRATION.md`). 실제 SDK 어댑터 연결과 실기기 검증은 Mac으로 넘깁니다. `docs/LAUNCH_CONTENT_AUDIO_COMMERCE.md`와 `docs/MAC_PLATFORM_ADAPTER.md`가 최신 구현 상태입니다. 실제 난이도/청감 검수와 iOS 업데이트 설치 검증은 남았습니다.

## 제품 목표와 작업 방식

- 기본 무료, IAP(인앱 구매)와 IAA(인앱 광고)를 결합한 캐주얼 퍼즐입니다.
- 짧고 이해하기 쉬운 플레이, 만족스러운 수집 연출, 공정한 난이도와 지속적인 레벨 진행으로 재방문을 유도합니다.
- Windows에서 Codex가 통합·수정·검증을, Gemini가 큰 코드 초안·대량 콘텐츠 초안을 담당합니다. 사용자가 프롬프트와 결과를 전달합니다.
- 첫 플랫폼은 iOS이며 Google Play는 후속입니다. 최종 iOS 빌드, 실제 SDK 검증, 서명, TestFlight와 제출은 Mac mini에서 수행합니다.
- 자체 서버 없이 시작합니다. 설치 후 기본 플레이, 저장과 이미 획득한 비소모성 권한은 가능한 범위에서 오프라인으로 동작합니다.

## 기술 방향

- 웹은 규칙 검증과 빠른 플레이테스트용으로 유지합니다. 출시 클라이언트는 기존 구조를 활용한 Godot 4의 2D 구현을 우선 후보로 합니다.
- 엔진 버전은 광고·StoreKit 플러그인의 유지보수 상태, 라이선스, 지원 iOS/Xcode 버전을 확인한 뒤 최종 고정합니다. 현재 Windows 검증 버전은 Godot 4.7.2입니다.
- 엔진을 확정하기 전에 StoreKit 구매/복원과 광고 플러그인의 작은 통합 실험을 합니다. 비용이나 호환성 문제가 크면 본격 이식 전에 Unity 등 대안을 비교합니다.
- Godot Main 씬과 순수 코어, 300레벨과 튜토리얼/힌트·로컬 완료 기록, 음악/효과음·수집/완성 연출, 상점·모의 결제/광고 흐름을 통합했습니다. 미술과 실제 네이티브 SDK 연결·실기기 확인은 남았습니다.
- 순수 규칙 코어, 레벨 데이터, 표현/UI, 저장소, 플랫폼 서비스를 분리합니다. 코어는 광고·결제·게임센터를 알지 못합니다.
- 원본 레벨은 `godot-project/data/levels.json`입니다. 웹은 `python tools/level_builder.py`로 같은 데이터를 내장합니다.
- 로컬 세이브에는 버전과 마이그레이션, 임시 파일/백업을 이용한 안전한 쓰기, 손상 복구를 둡니다. 웹의 개발용 초기화 정책을 출시 세이브에 그대로 적용하지 않습니다.

| 항목 | 첫 출시 선택 | 비용/한계 |
| --- | --- | --- |
| 게임 진행·레벨·설정 | 기기 내 저장, 내장 콘텐츠 | 자체 서버 사용료 없음. 삭제/기기 교체 시 진행 유실 가능성을 안내 |
| 결제 | Apple StoreKit, 이후 Google Play Billing | 스토어 수수료 발생. 자체 결제 서버는 첫 출시에서 두지 않음 |
| 광고 | 단일 광고 네트워크(AdMob 우선 검토) | 별도 게임 서버 불필요. 승인·정책·SDK 호환성과 수익 지급 조건 확인 필요 |

Apple Developer Program의 일반적인 기준 비용은 연 US$99이며 지역 가격·세금·가입 시점 공식 조건을 확인합니다. 스토어 수수료, 자산/사운드 라이선스와 선택적 도구 비용은 서버비와 별개입니다. Godot 자체에는 엔진 로열티가 없지만 사용하는 플러그인의 조건은 개별 확인합니다.

무료 플랜을 넘어설 때는 먼저 기능 축소, 캐시, 요청 빈도 제한, 플랫폼별 Game Center/Play Games 사용을 비교합니다. Firebase 유료 전환이나 유료 플러그인 구매는 사용자와 비용을 확인한 뒤 진행합니다. 예산 알림을 과금의 강제 상한으로 취급하지 않습니다.

## 첫 출시 수익화 범위

- 상점: 광고 제거 비소모성 상품 1개, 스타터팩 1개를 우선 설계합니다. 스타터팩 구성·상품 유형·최종 가격은 경제 밸런스와 복원 정책을 정한 뒤 확정합니다.
- 광고 제거는 강제 전면 광고를 제거합니다. 사용자가 선택하는 보상형 광고는 남는다는 점을 구매 전에 명확히 표시합니다.
- 보상형 광고: 막힘 상태의 제한적 추가 슬롯/이어하기 또는 무료 보조 아이템 획득을 우선 검토합니다. 효과와 횟수는 무료 플레이 균형을 먼저 검증합니다.
- 전면 광고: 첫 튜토리얼 구간 제외, 레벨 종료 등 자연스러운 전환에서만 노출합니다. 빈도 제한을 데이터로 관리하고 처음에는 보수적으로 조정합니다.
- 배너, 구독, 확률형 유료 아이템은 초기 범위에서 제외합니다.
- 광고가 준비되지 않거나 네트워크가 없으면 적절한 안내와 무료 재시작 경로를 제공합니다. 광고 로드 실패를 게임 진행의 필수 장벽으로 만들지 않습니다.
- 보상은 광고 SDK의 정식 보상 완료 콜백에서만 한 번 지급합니다. 취소·실패·중복 콜백·앱 중단을 처리합니다.
- 결제는 검증된 StoreKit 트랜잭션과 안정적인 거래 ID로 처리합니다. 중복 지급, 대기/취소/실패, 환불/권한 변경, 비소모성 복원을 다룹니다.
- 로컬 소모성 재화는 변조와 재설치 복원의 한계가 있습니다. 공용 경쟁 재화나 현금 가치 거래에 사용하지 않습니다. 서버 없는 설계에서 완전한 치트 방지를 약속하지 않습니다.

## 리텐션과 측정

- 우선 20개의 클리어 가능한 레벨로 튜토리얼, 난이도 상승, 새 기믹 소개를 검증하고 이후 콘텐츠를 늘립니다. 20개는 플레이테스트 묶음이며 출시 콘텐츠 수 확정이 아닙니다.
- 출석/일일 도전 등은 기본 재미가 검증된 뒤 도입합니다. 로컬 날짜 기반 콘텐츠는 시간 변경에 취약하므로 글로벌 랭킹이나 유료 보상과 연결하지 않습니다.
- 첫 출시에는 Game Center가 필수는 아닙니다. 동일 조건 일일 도전, 최소 사출 수 경쟁 등 비교 가능한 모드가 실제로 재미에 기여할 때 추가합니다.
- 내부 이벤트 명세에 레벨 시작/완료/실패, 사출 수, 시도 횟수, 재시작, 광고 제안/보상, 구매 결과를 정의합니다. 개발 로그와 실제 수집 SDK는 분리합니다.
- D1/D7, 레벨별 이탈·완료율, 세션 길이, 보상형 광고 선택률 등을 보고 조정합니다. 이 수치는 텔레메트리와 충분한 표본 없이 측정할 수 있다고 주장하지 않습니다.
- 실제 분석 SDK 도입은 무료 조건과 개인정보 영향을 확인한 뒤 결정합니다. 초기는 App Store Connect와 광고 대시보드를 활용하되 퍼널/리텐션 분석의 한계를 구분합니다.

## 단계별 완료 조건

1. 플랫폼 타당성: Godot/플러그인 후보, 라이선스, 지원 환경과 네이티브 연결 방식을 기록합니다. 가능하면 작은 Mac SDK 실험을 먼저 합니다. 끝까지 Windows만 쓸 경우 이 항목을 미검증 위험으로 명시합니다.
2. 네이티브 플레이 가능 버전: 순수 코어와 Main 씬, 웹과 일치하는 두 레벨, 사출/수집/막힘/클리어/2배속/Undo/저장/복원. Windows에서 실행하고 두 레벨의 클리어를 검증합니다.
3. 재미 검증: 튜토리얼과 레벨 팩, 효과음/진동/수집 연출, 일시정지·설정·접근성. 해결 가능성 외에 의사결정과 체감 난이도를 플레이테스트합니다.
4. 수익화 구조: 상점, 무료 재화/부스터, AdsService/BillingService/LeaderboardService 인터페이스 및 모의 구현. 실패와 중복 호출을 포함한 흐름을 Windows에서 검증합니다. 모의 결제 성공은 실제 구매 완료와 구분합니다.
5. Windows 인계 준비: 콘텐츠 동결 후보, 플러그인/엔진 버전, export 설정의 안전한 템플릿, 상품 ID/광고 ID 자리표시자 목록, 리소스 라이선스, 세이브 마이그레이션, QA 결과, Mac 실행 절차를 갖춥니다. 비밀키는 저장소에 넣지 않습니다.
6. Mac 실기기: Xcode/서명, StoreKit 샌드박스 구매·복원, 테스트 광고와 보상, 선택적 Game Center, 기기별 성능/안전 영역/중단 복구, 개인정보 동의와 ATT 필요 여부, 앱 개인정보/SKAdNetwork 등 SDK 요구사항을 검증합니다.
7. TestFlight 및 제출: 내부/외부 테스트, App Store 메타데이터와 심사 정보, 최종 상품·광고 설정, 개인정보처리방침 공개 URL, 연령 등급과 지원 연락처를 준비합니다. 정적 정책 페이지는 무료 호스팅을 검토합니다.

Windows 작업 종료는 5단계 완료를 의미합니다. 6~7단계는 Mac과 실제 개발자 계정이 필요한 별도 필수 작업입니다.

현재 3단계의 검증 도구로 독립 저장을 사용하는 레벨 선택 실행(`godot.ps1 playtest`)과 실제 코어의 40회 템포 재생(`godot.ps1 pacing`)을 추가했습니다. 절차는 `docs/PLAYTEST_GUIDE.md`, 측정 결과는 `docs/PLAYTEST_BASELINE.md`입니다. 사람의 재미·체감 난이도 평가는 아직 수집 전입니다.

## 다음 Gemini 작업

`docs/GEMINI_NEXT_TASK.md`와 `docs/handoffs/`는 지난 요청의 기록입니다. 현재 300레벨·개선한 연출/음악·상점/모의 서비스까지 통합했고 게임 검사 553개, 서비스 검사 43개, Godot/웹 각각 1,200회 레벨 재생을 통과했습니다. 후속 Gemini에는 최신 소스와 표본 레벨을 제공해 생성 레벨의 실제 선택지·반복감·난이도 가설 검토를 배치 단위로 맡깁니다. 실제 SDK 연결과 기기 검증은 Mac 인계 문서를 따릅니다.
