# Gemini 다음 작업: Godot 플레이 가능 버전

현재는 그래픽 교체를 미루고 300레벨·음원/연출·상점/모의 서비스 흐름까지 구현했습니다. `docs/LAUNCH_CONTENT_AUDIO_COMMERCE.md`가 최신 현황입니다. 후속 Gemini에는 현재 소스를 새로 제공하고 생성 레벨의 난이도·선택지 검토를 배치 단위로 맡기는 것이 적합합니다. 아래 파일들은 과거 요청 기록입니다.

최근 템포 후보 요청의 통합을 완료했습니다. 13레벨을 채택하고 18레벨의 수량·해법을 수정해 반영했으며 7레벨은 기존 배치를 유지합니다. 검토는 `docs/PACING_CANDIDATE_REVIEW.md`, 다음 수동 테스트는 `docs/PLAYTEST_GUIDE.md`를 참고하세요. `docs/handoffs/gemini-pacing-review-input.txt`도 과거 스냅샷이므로 그대로 재요청하지 않습니다.

> 아래 이식 작업, 20레벨 제작, 일시정지·설정·플레이 피드백은 통합 완료된 과거 요청입니다. 결과는 `docs/PLAY_FEEDBACK_TASK.md`에 기록했습니다. 인계 파일은 과거 소스 스냅샷이므로 후속 요청 시 현재 소스를 새로 제공해야 합니다.

사용자 전달용 입력 파일은 `docs/handoffs/gemini-godot-input.txt`입니다. 이 텍스트 파일 전체를 첨부하거나 내용을 붙여 넣으세요. 소스는 이 인계 시점의 스냅샷이며, 이후 작업에는 현재 파일을 다시 제공해야 합니다.

아래 프롬프트는 인계 파일에도 포함되어 있습니다.

```text
너는 CarLoop 색상 블록 정렬 퍼즐의 Godot 구현 담당이다.
첨부한 텍스트의 실제 소스를 읽고 Windows에서 실행 가능한 Godot 4 2D 버전을 작성해줘.
웹은 규칙 검증용이고, 최종 목표는 iOS 무료 게임(IAP+IAA), 이후 Android다.
이번 작업은 기본 게임의 네이티브 이식이며, 실제 결제·광고·서버·Game Center는 구현하지 않는다.
HubGame, Three.js, 무기/행성 미션은 이 프로젝트와 관계없다.

읽기 확인: 웹의 GameCore.updateProgress, validSnapshot, checkDeadlock과
Godot project.godot의 main_scene 경로를 각각 확인한 뒤 작업을 시작해라.
소스를 읽을 수 없으면 추정 코드를 만들지 말고 필요한 파일만 알려줘.

구현 요구사항:
1. 현재 웹의 규칙을 기준으로 순수 GDScript GameCore를 작성한다.
   코어는 Node, UI, 파일, 광고·결제 SDK에 의존하지 않는다.
2. 공용 res://data/levels.json을 그대로 사용한다. 임의의 레벨/경제/부스터를 추가하지 않는다.
3. lane이 수집 노드이며 잠긴 차량은 수집하지 않는다. 입구 통과 시에만 수집한다.
   트랙 가득 참 + 수집 불가능이면 남은 차량 블록과 무관하게 막힘이다.
4. 사출, 색상별 블록 보존, 자동 수집, 차량 완성, 전체 클리어,
   순환 이동, 1x/2x, Undo(20개), Shuffle(표시 순서만), Reset을 구현한다.
5. 120Hz 고정 시뮬레이션, delta 상한 0.1초, 포커스 복귀 시 누적 시간 초기화를 적용한다.
6. Main.tscn과 Main.gd를 제공하여 프로젝트를 열고 바로 플레이할 수 있게 한다.
   입력->코어->상태->뷰 흐름을 유지하고 매 프레임 전체 UI를 재생성하지 않는다.
7. 스마트폰 세로 화면, 안전 영역, 다양한 종횡비, 터치/마우스를 지원한다.
   임시 도형/기본 UI로 동작을 검증하며 외부 이미지·폰트·애드온 의존성을 추가하지 않는다.
8. user://에 저장하며 저장/복원 실패로 게임이 중단되지 않게 한다.
   버전, 레벨 식별자, 상태 검증, 이전 정상 백업과 원자적 교체를 고려한다.
   iOS 생명주기와 포커스 상실/종료 알림에서 저장하며, 매 프레임 쓰지 않는다.
9. 코어는 클리어 후 다음 레벨로 스스로 전환하지 않는다.
   컨트롤러는 전환을 한 번 예약하고 Undo/Reset/재시작 때 이전 예약을 취소한다.
10. 기존 autoload와 class_name 충돌, 잘못된 project.godot 형식,
    존재하지 않는 Main 씬 등 실행 방해 요소를 실제 제공 소스 기준으로 수정한다.
11. 기존 스캐폴드 스크립트는 통합하거나 역할을 명시한다.
    실제 동작과 충돌하는 중복 코어를 두지 않는다.
12. 헤드리스로 실행할 검증 스크립트를 제공한다.
    두 레벨 각각 A 4회->B 4회->C 4회(각 사출 뒤 수집 대기)의 클리어,
    60/120Hz 동일 속도, 2배속, 블록 보존, Undo, 막힘, 잘못된 저장 데이터를 검사한다.

답변 형식:
- 실제 확인한 소스와 설계 결정 10줄 이내.
- 추가/수정할 파일별 경로와 생략 없는 전체 코드. 인라인 코드 주석은 넣지 않는다.
- Windows 실행법과 헤드리스 검사 명령.
- 실제 실행한 검사와 미실행 검사를 명확히 구분한다.
- Mac/iOS 실기기 검증이 필요한 내용은 별도로 표시한다.
토큰을 아끼기 위해 변경하지 않은 파일과 레벨 JSON은 다시 출력하지 않는다.
출력이 길면 의존 순서대로 파일을 완성해서 나누고, 파일 중간에서 생략하지 않는다.
```
