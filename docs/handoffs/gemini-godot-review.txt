앞서 제공한 Godot 구현을 실제 소스와 요구사항에 맞게 수정해줘.
이 프로젝트는 네이티브 Godot iOS 게임이며 웹뷰 게임이 아니다.
Windows에서 구현하고 Mac에서 최종 iOS SDK/실기기/TestFlight 검증을 한다.
아래 문제 때문에 아직 저장소에 코드를 통합하지 않았다.

필수 수정:

1. HubGame을 완전히 제거한다.
   HubIntegration.gd, JavaScriptBridge, leaderboard_panel, hub_user_lbl,
   HubGame 폴링/점수 전송, 웹 저장 폴백 정책은 이 작업에 필요 없다.
   이전 답변의 data-save-leaderboard.txt 등은 제공된 프로젝트 요구사항이 아니다.
   외부 가이드가 존재하거나 검토되었다고 추정하지 말고 제공된 소스를 기준으로 한다.

2. 실제 프로젝트 실행 방해 요소를 수정한다.
   autoload 이름 GameManager와 같은 class_name GameManager를 선언하지 않는다.
   기존 project.godot의 첫 줄 [gd_resource ...]를 포함해 파일을 실제 프로젝트 설정 형식으로 정리한다.
   Main.tscn을 추가하고 잘못되거나 불필요한 uid를 제거한다.
   기존 스캐폴드 LevelController/TrackQueue/BoosterController는 어떻게 대체하거나
   정리할지 명시한다. 사용하지 않는 모순된 규칙을 새 코어와 연결하지 않는다.

3. GameCore의 저장 검증을 강화한다.
   인자를 Dictionary로 강제해 잘못된 데이터에서 호출 오류가 나게 하지 말고,
   Variant의 타입과 필드 존재 여부를 먼저 검사해 false로 반환한다.
   levelIdx/speed/배열/차량/블록/트랙 항목/history/cleared의 모든 타입을 검사한다.
   levelIdx와 ID는 유한한 정수, progress는 유한하며 범위 내인 숫자여야 한다.
   중복 차량 ID, 중복 트랙 ID, 중복 cleared ID, 알 수 없는 색상/차량,
   변조된 메타데이터, 불일치한 완료 상태, 색상별 블록 수량 손실을 거부한다.
   유효하지 않은 load_state 호출은 현재 정상 상태를 바꾸지 않는다.
   JSON 숫자가 float으로 파싱되는 경우 정상 정수값을 허용하고 안전하게 정규화한다.
   update_progress는 NaN/무한 delta를 거부한다.

4. 실제 안전한 로컬 저장과 복원을 구현한다.
   페이로드에 version과 레벨 호환성 식별자를 포함한다.
   temp에 쓰기/flush/close 성공을 확인하고, 기존 정상 세이브를 .bak으로 보존한다.
   기존 유일한 정상 파일을 먼저 삭제한 뒤 rename하는 현재 방식을 제거한다.
   파일 이동/쓰기의 Error 결과를 확인하고 실패 시 정상 파일을 복원한다.
   주 파일의 JSON 파싱뿐 아니라 코어 상태 검증이 실패해도 정상 백업 후보로 복원한다.
   무효한 주 파일을 정상 백업 위에 덮어쓰지 않는다.
   저장 실패로 게임이 종료되지 않게 하며 UI에 저장 불가 상태를 표시한다.

5. 저장 시점을 보완한다.
   사출/수집/배속 변경/Undo/Shuffle/Reset/레벨 전환 시 변경을 저장한다.
   이동 위치 저장은 최대 초당 한 번으로 제한한다. 정지 상태에서는 반복 저장하지 않는다.
   현재 _on_speed_pressed와 자동 수집 후에는 저장이 빠져 있다.
   실제 Godot 알림/시그널을 사용해 포커스 상실, 앱 일시정지, 종료에서 저장한다.
   존재 여부를 확인하지 않은 Viewport.application_focus_out 시그널을 사용하지 않는다.
   복귀 시 core.accumulator와 경과 시간을 초기화하고 백그라운드 시간만큼 이동하지 않는다.

6. 플레이 가능한 렌더러로 수정한다.
   trackNodes 좌표를 보간해 실제 닫힌 순환 경로를 그린다. 현재 가로 한 줄 이동은 요구사항에 맞지 않는다.
   수집 입구 A/B/C, 트랙 점유량, 블록 색상, 각 차량 내부 블록의 앞->뒤 순서를 표시한다.
   _render_dynamic에서 매 프레임 queue_free/new 하지 않는다.
   블록 ID별 노드를 재사용하거나 별도 draw 기반 렌더러를 사용한다.
   동적 노드 삭제 직후 같은 프레임 중복 노드가 보이지 않게 한다.
   터치 가능한 버튼 크기와 세로 화면에서 스크롤/축소 대응을 제공한다.
   고정 40px 여백을 safe area 처리로 부르지 말고
   DisplayServer.get_display_safe_area와 뷰포트/윈도 좌표 변환을 고려한다.
   Windows/헤드리스에서 안전 영역을 얻을 수 없을 때는 전체 뷰포트를 사용한다.

7. 컨트롤러 상태 전환을 명확히 한다.
   클리어 전환을 한 번 예약하고 Undo/Reset/재시작으로 취소한다.
   전환 직후 예약 상태를 명시적으로 초기화한다.
   float 타이머가 정확히 0이 될 때 다음 클리어가 예약되지 않는 경계를 없앤다.
   막힘 해소 후 과거 막힘 메시지가 남지 않게 한다.
   레벨 로딩 실패/빈 데이터/파일 열기 실패를 처리한다.

8. 출력용 로그가 아닌 실제 헤드리스 검증을 제공한다.
   실패를 수집하고 실패가 있으면 quit(1), 통과하면 quit(0)으로 종료한다.
   update_progress(0.6)은 0.1초로 제한되므로 수집 대기가 되지 않는다.
   1/60초 또는 1/120초를 반복 호출해 시간을 진행한다.
   두 레벨 각각 A4회->B4회->C4회, 각 사출 후 4.2초 시뮬레이션으로 실제 클리어를 검사한다.
   60/120Hz 동일 속도, 2배속, 색상별 블록 보존, Undo, 최대 20개 히스토리,
   차량에 블록이 남아 있는 full+uncollectable 막힘, 손상/악성 저장 데이터,
   재로드 후 블록 ID 충돌 방지와 저장 백업 복구를 검사한다.
   타이머 취소/일회성 전환은 컨트롤러 검증으로 따로 다룬다.
   검증용 저장 파일은 실제 플레이 세이브와 다른 경로를 사용한다.

출력은 수정/추가한 파일별 경로와 생략 없는 전체 코드로 제공한다.
변경 없는 레벨 JSON 등은 다시 출력하지 않는다. 인라인 코드 주석을 추가하지 않는다.
기존 파일을 삭제해야 하면 그 경로와 이유도 명시한다.
Godot 실행 환경이 없다면 실행 검증했다고 쓰지 말고 미실행으로 표시한다.
헤드리스 import, 테스트 실행, GUI 실행의 Windows 명령도 함께 제공한다.
결과가 길면 완전한 파일 단위로 나누고 파일 중간에서 생략하지 않는다.
