# 첫 플레이테스트

현재 단계는 재미와 조작 이해도를 확인하는 것입니다. 자동 재생 성공은 재미·체감 난이도·리텐션을 증명하지 않습니다. 아직 사람의 플레이 결과는 수집하지 않았습니다.

현재 300레벨과 개선한 사운드/연출·상점 모의 흐름이 있습니다. 13·18레벨 비교에 더해 21·60·120·180·240·300에서 생성 배치의 반복감과 난이도를 표본 확인합니다. Windows 디버그 상점은 실제 결제/광고가 아니며 모의 보상/권한도 테스트 저장 파일에 분리됩니다.

## 실행

저장소 폴더에서 실행합니다. 테스트 모드는 기본 게임과 다른 진행/설정 파일을 사용하며 지정 레벨을 새 배치로 시작합니다. 테스트 중 진행과 설정은 테스트 파일 안에서 저장됩니다.

```powershell
.\tools\godot.ps1 playtest
.\tools\godot.ps1 playtest -LevelId level-011 -Speed 1
.\tools\godot.ps1 playtest -LevelId level-011 -Speed 2
.\tools\godot.ps1 playtest -LevelId level-013 -Speed 1
.\tools\godot.ps1 playtest -LevelId level-018 -Speed 1
.\tools\godot.ps1 pacing
```

마지막 명령은 `docs/PLAYTEST_BASELINE.md`를 다시 생성합니다. 게임 파일과 세이브는 변경하지 않습니다.
테스트 중에는 `user://carloop_playtest.json`과 별도 `carloop_playtest_settings.json`을 사용합니다. 일반 실행은 `.\tools\godot.ps1 play`입니다.

## 약 10~15분 진행 순서

1. 정답 파일을 열지 않고 1~5레벨을 이어서 플레이합니다. 첫 시도는 1x로 시작하고 원할 때 2x로 바꿉니다.
2. 이번에 바뀐 13·18레벨을 먼저 골라 플레이합니다. 시간이 남으면 8·11·15·19·20레벨도 확인합니다. 2분 이상 진행 방향을 못 찾으면 중단으로 적고 넘어갑니다. 이 시간은 테스트 편의를 위한 기준입니다.
3. 각 레벨에서 사출 수보다 무엇을 보고 다음 차량을 골랐는지, 기다리는 동안 할 일이 있었는지 기록합니다.
4. 진행 중 일시정지→설정→닫기를 눌렀을 때 정지가 유지되는지 확인합니다. 효과음/연출 줄이기를 바꿔 어떤 쪽이 편한지도 적습니다.
5. 어려웠던 레벨 하나를 2x로 다시 합니다. 속도 때문인지 순서 판단 때문인지 구분해 적습니다.

스톱워치의 레벨 시간에는 생각·터치를 포함하고 의도적으로 쉬거나 메뉴를 확인한 시간은 제외합니다. 1x/2x를 섞었다면 배속 칸에 적습니다. 이 기록을 자동 재생 시간과 직접 비교하지 않습니다.

## 현재 검토할 가설

- 두 색 차량의 앞 블록과 목표 색을 구분하고, 차량을 비워야 수집할 수 있음을 첫 3레벨에서 이해하는가?
- 4~5레벨의 용량 제한과 Undo가 실수 복구를 가르치는가? 무작정 여러 번 탭하게 만드는가?
- 6~7레벨은 자동 재생 지표가 같습니다. 색·차선·배열 차이를 사람이 다른 선택으로 느끼는지 확인합니다. 정확히 같은 배치는 아닙니다.
- 11레벨 이후 같은 차량 4연속 사출이 반복 작업처럼 느껴지는가? 다른 해법으로 즐길 여지가 있는가?
- 2x가 선택 가능한 편의인지, 기다림을 견디기 위해 사실상 필수인지 확인합니다.
- 수정한 13레벨에서 목표 색을 남기는 이유와 18레벨에서 작은 D 차량의 용도를 알아차리는지 확인합니다. 자동 재생에서 사출 수가 줄었지만 체감 난이도 변화는 미검증입니다.
